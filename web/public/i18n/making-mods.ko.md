# Horizon 모드 만들기

Horizon Translator의 **모드 만들기** 탭에서는 Minecraft Java의 Rust 재작성 버전인 [Horizon](https://github.com/horizon-rust/horizon)용 모드를 제작할 수 있습니다. 코딩을 전혀 하지 않고도 모드를 만들 수 있으며, 나중에 소스 코드를 열어 더 깊이 있는 개발을 진행할 수도 있습니다.

- **코드 불필요:** 원하는 기능에 체크하고 양식을 채운 뒤 **모드 만들기**를 누르면 완성된 `.hnmod` 파일이 생성됩니다.
- **코드 포함:** 모든 모드에는 Rust 소스 코드, 테스트 구성 및 검사 버튼이 함께 제공되어 개발 시작 키트로 활용할 수 있습니다.
- **지속적인 호환성:** 키트 모드는 Horizon 개발팀이 모드용으로 안정성을 유지하는 핵심 인터페이스(후크 포인트)만 사용하므로, Horizon이 업데이트되어도 런처에서 바로 빌드할 수 있습니다. 업데이트마다 매번 새로 만들 필요가 없습니다.
- **자동 업데이트 확인:** 앱이 시작될 때 GitHub에서 최신 버전을 확인하여 안내합니다. 새 버전마다 빌더와 가이드에 새로운 기능이 추가됩니다.

## 빠른 시작

1. 웹사이트(또는 GitHub Releases 페이지)에서 Windows 또는 Linux용 Horizon Translator를 다운로드하여 실행합니다.
2. **모드 만들기** 탭을 엽니다. **시작 템플릿**에서 예제를 골라 **사용**을 누르거나 빈 모드로 시작합니다.
3. 모드 **이름**을 입력합니다. **모드 ID**는 자동으로 생성되며, 같은 모드의 새 버전을 만들 때도 동일한 ID를 유지해야 합니다.
4. 원하는 기능(HUD 상자, 채팅 명령어, 단축키, 줌, 채팅 메시지)을 선택하고 내용을 입력합니다.
5. **Horizon에 등록하기**에 체크한 상태에서 **모드 만들기**를 누릅니다.
6. Horizon 런처의 **모드** 페이지에서 "Horizon 네이티브 빌드" 아래의 **빌드**를 누릅니다(보이지 않는 경우 먼저 **설정 > 게임 > 네이티브 모드**를 켜세요). 첫 빌드 시에는 Rust를 다운로드하므로 20~30분 정도 걸리며, 이후 빌드는 몇 분이면 완료됩니다.
7. 게임을 실행합니다. 채팅창에 `/<모드 ID>`를 입력하여 등록된 명령어와 단축키 목록을 확인하세요.

모드는 `Documents/Horizon Translator/<mod id>/` 폴더에 저장됩니다(앱 하단에서 저장 폴더 변경 가능).

## 코딩 없이 만들 수 있는 기능

### HUD 상자

화면 모서리에 좌표, 바라보는 방향, FPS 등의 텍스트를 표시합니다. 각 줄마다 일반 텍스트와 플레이스홀더(아래 참고)를 자유롭게 조합할 수 있습니다. F1 키를 누르면 자동으로 숨겨지며, F3 디버그 화면과 겹치지 않도록 위치를 피합니다. 글자 색상, 반투명 검은색 배경 상자 표시 여부, 표시/숨김 단축키를 설정할 수 있습니다. 플레이어는 **설정 > 모드**에서 이를 비활성화할 수도 있습니다.

### 채팅 명령어

플레이어가 `/hello`처럼 채팅창에 입력하는 명령어입니다. 다음 동작을 수행할 수 있습니다:

- **채팅창에 출력:** 한 줄 또는 여러 줄의 텍스트 표시(입력 상자에서 줄 구분은 `|` 문자 사용).
- **HUD 상자 표시/숨김 전환.**
- **줌 확대/축소 전환.**

명령어는 서버에 도달하기 전 플레이어의 로컬 게임에서 먼저 가로채어 실행되므로 어떤 멀티플레이 서버에서도 동작합니다. 서버 표준 명령어(`/help`, `/home`, `/spawn` 등)와 같은 이름을 사용하면 모드가 해당 명령어를 덮어쓰게 되므로 피하세요. `/<mod id>` 명령어는 항상 자동 등록되어 모드의 명령어와 단축키 목록을 안내합니다.

### 단축키

명령어와 동일한 동작을 수행하는 키입니다. 플레이어는 **설정 > 모드 > 해당 모드**에서 각 키 바인딩을 변경할 수 있습니다. 단축키는 게임 플레이 중에만 반응하며 채팅창 입력 중이나 메뉴가 열려 있을 때는 작동하지 않습니다.

### 줌

OptiFine 스타일의 줌 기능: 확대 배율(1.5배~10배), 누르는 동안만 확대할지 토글식으로 켜고 끌지 여부, 망원경과 같은 부드러운 전환, 줌 상태에서 마우스 휠로 배율 미세 조절 등을 지원합니다. 줌 작동 중에는 마우스 시점 회전 속도가 자연스럽게 감속됩니다.

### 채팅 메시지

- **접속 환영 메시지:** 월드에 접속했을 때 채팅창에 표시되는 안내 텍스트.
- **정기 알림 메시지:** 플레이 중 지정된 분 간격으로 주기적으로 표시되는 알림(월드 접속 시점부터 시간 측정).

메시지는 본인 화면에만 출력되며 서버로 전송되지 않습니다.

### 플레이스홀더

모든 텍스트 상자에서 사용 가능하며, 텍스트가 표시될 때 실시간 정보로 자동 치환됩니다.

| 플레이스홀더 | 표시 내용 |
|---|---|
| `{x}` `{y}` `{z}` | 현재 위치(소수점 한 자리): `12.3` |
| `{bx}` `{by}` `{bz}` | 현재 서 있는 블록 좌표: `12` |
| `{facing}` | 바라보는 방위: `North (-Z)`, `East (+X)`, `South (+Z)`, `West (-X)` |
| `{yaw}` `{pitch}` | 시선 방향(도 단위) |
| `{dimension}` | 차원: `Overworld`, `Nether`, `End` |
| `{fps}` | 초당 프레임 수 |
| `{name}` `{version}` | 모드 이름 및 버전 |

### 플레이어 제공 설정

모든 키트 모드는 **설정 > 모드**에 개별 행이 생성되어 할당된 단축키와 각 구성 요소(HUD 상자, 줌, 환영 메시지, 정기 알림)의 ON/OFF 버튼을 제공합니다. 플레이어는 여기서 모드 전체를 끌 수도 있습니다.

## 새 버전 만들기

1. **제작한 모드 열기…**를 누르고 기존 모드 폴더를 선택합니다. 이전에 선택했던 양식 내용이 복원됩니다.
2. 원하는 내용을 수정하고 **버전** 번호를 올립니다(예: 1.0.0 → 1.1.0).
3. **모드 만들기**를 누릅니다. 새 버전은 기존 폴더를 덮어쓰지 않고 새 폴더(`<mod id>-2` 등)에 안전하게 저장되며, Horizon 내부의 기존 `.hnmod`를 갱신합니다. 런처에서 다시 빌드하세요.

**모드 ID**는 변경하지 마세요. Horizon은 모드를 ID로 식별하므로 ID를 유지해야 플레이어의 기존 설정과 단축키가 그대로 유지됩니다.

## 모드 공유하기

완성된 `.hnmod` 파일을 공유하면 됩니다. 플레이어는 런처의 모드 페이지에서 가져오거나, Windows의 `%APPDATA%\horizon\horizon-native-mods\`, Linux의 `~/.local/share/horizon/horizon-native-mods/` 경로에 복사한 후 빌드하면 됩니다.

네이티브 모드는 게임 내부로 직접 컴파일되며 플레이어 시스템 권한으로 실행됩니다(샌드박스 처리되지 않음). 따라서 런처는 빌드 전에 확인 메시지를 표시합니다. 내용을 직접 알고 있는 모드만 공유하고, 신뢰할 수 있는 개발자의 모드만 설치하세요.

## 심화 개발: 소스 코드

모든 모드 폴더는 독립적인 소형 Rust 프로젝트로 구성되어 있습니다:

| 파일 | 설명 |
|---|---|
| `mixins/<id>/runtime.rs` | 모드 핵심부. 상단은 설정(텍스트, 키, 명령어), 중간은 로직, 하단은 테스트 |
| `mixins/<id>/key.rs`, `hud.rs`, `command.rs`... | 후크: Horizon이 호출할 때 실행(단축키, HUD, 명령어, 틱) |
| `mixins/<id>/horizon-mixin.toml` | 어떤 후크 포인트가 어떤 파일을 실행할지 지정하는 설정 |
| `Cargo.toml` | 게임을 실행하지 않고 `cargo test`로 `runtime.rs`의 테스트를 실행할 수 있게 함 |
| `compatibility.json` | 모드가 요구하는 후크 포인트 버전 및 기준 Horizon 커밋 |
| `horizon-kit.json` | 모드 제작 도구 양식에서 선택한 설정 내용 |
| `<id>.hnmod` | 패키징된 완성 모드 파일 |

코드를 직접 수정하려면:

1. 선호하는 에디터(rust-analyzer 확장이 설치된 VS Code 권장)로 파일을 수정합니다.
2. 앱에서 **모드 만들기 > 폴더 확인 및 패키징…**을 누르고 모드 폴더를 선택합니다. Rust(rustup.rs)가 설치되어 있으면 Horizon의 모드 헬퍼에 맞춰 컴파일 검사와 테스트를 먼저 수행합니다. Rust가 없으면 즉시 패키징되며 문제 발생 시 런처 빌드 단계에서 오류를 알려줍니다. 이후 새 `.hnmod`가 패키징되어 Horizon에 등록됩니다.
3. 런처에서 빌드하고 게임을 실행하여 확인합니다.

**코드를 수동으로 수정한 모드에 대해 "모드 만들기" 버튼을 누르지 마세요:** 양식 내용으로 소스 코드가 초기화되어 덮어쓰여집니다. 수동 편집 후에는 항상 "폴더 확인 및 패키징"을 사용하세요.

### 명령줄 도구(및 AI 코딩 에이전트용)

앱에 내장된 `horizon-port.jar`를 사용하면 터미널에서 동일한 작업 및 정밀 컴파일 검사를 수행할 수 있습니다. 각 모드 폴더에는 AI 코딩 에이전트를 위한 명령어 안내 문서인 `AGENTS.md`와 모든 후크 포인트 및 헬퍼를 정리한 `HOOKS.md`가 포함되어 있습니다.

| 명령어 | 수행 작업 |
|---|---|
| `java -jar horizon-port.jar new spec.json --out DIR --horizon-src SRC` | 제작 도구 스펙으로부터 모드 생성(`kit-examples/`에 예제 포함) |
| `java -jar horizon-port.jar hooks --horizon-src SRC [--json]` | 해당 Horizon 버전의 후크 포인트 및 헬퍼 목록과 각 후크의 `[[injection]]` 표시 |
| `java -jar horizon-port.jar compile DIR --horizon-src SRC` | 전체 검사: 런처와 동일하게 모드를 Horizon 사본에 넣고 컴파일 |
| `java -jar horizon-port.jar pack DIR --horizon-src SRC --compile --install` | 전체 검사, 테스트 실행, 패키징, Horizon에 추가를 한 번에 수행 |

`SRC`는 Horizon의 소스 코드 경로이며 `compile` 수행 시 압축 해제됩니다. `compile`은 Rust와 런처의 horizon-mixins 도구(최초 네이티브 빌드 시 자동 설치)를 필요로 하며, 첫 실행 시 수 GB의 용량과 수 분의 시간이 소요됩니다. **확인 및 패키징**과 달리, 공개 후크 포인트 외부의 게임 내부 데이터(`game.player`, `game.items()` 등)를 직접 읽는 코드의 유효성도 함께 검증합니다.

### 후크 포인트 작동 원리

Horizon은 실행 중 특정 위치에서 빈 함수(**후크 포인트**)를 호출합니다. `horizon-mixin.toml`의 각 `[[injection]]` 설정은 해당 빈 함수의 시작 부분에 작성한 파일을 삽입합니다. 해당 파일은 단 하나의 함수를 포함하며 `bindings`에 선언된 매개변수를 전달받습니다. 예를 들어 `key.rs`는 게임 인스턴스, 키 이름, 눌림/뗌 상태를 전달받습니다:

```rust
fn my_mod_key(game: &mut crate::game::Game<'_>, key: &str, pressed: bool) {
    use crate::game::kit_my_mod as m;
    if !game.native_on(m::ID) {
        return;
    }
    if pressed && game.native_playing() && key == game.native_mod_key(m::ID, "jump_note", "key.keyboard.j") {
        game.native_chat("You pressed J");
    }
}
```

`runtime.rs`는 게임 본체에 모듈(`crate::game::kit_<id>`)로 삽입되는 동시에 프로젝트 자체의 독립 라이브러리로도 빌드됩니다. 따라서 게임 엔진이 필요 없는 순수 로직(수학 연산, 문자열 포맷, 모드 상태 데이터)은 여기에 작성하고 `cargo test`로 단위 테스트를 수행할 수 있습니다.

horizon-mixins 규칙: `runtime.rs` 내부에는 `//!` 주석이나 `#![...]` 속성, 외부 파일 참조를 위한 `mod x;`, `include!` 매크로를 사용할 수 없습니다. 모든 내용을 단일 파일에 작성해야 합니다(인라인 `mod x { ... }` 블록은 허용됨).

### 후크 포인트 목록

키트 모드를 구성하는 핵심 구성 요소입니다. 함수 이름과 매개변수는 Horizon 버전 전반에 걸쳐 하위 호환성을 유지합니다.

| 후크 포인트 | Horizon 호출 시점 | 전달되는 인자 |
|---|---|---|
| `native_frame` | 월드 진입 여부와 관계없이 매 프레임마다 | `elapsed: Duration` |
| `native_tick` | 게임 매 틱(초당 20회), 싱글플레이 서버에서도 호출: `native_window()` 확인 필요 | |
| `native_hud` | HUD를 그릴 때(F1 숨김 모드 제외) | `batch`, `corners`: `corners.place(corner, w, h)`로 상자 배치 |
| `native_key` | 키 또는 마우스 버튼을 누르거나 뗄 때(`key.keyboard.z`, `key.mouse.left`) | `key`, `pressed` |
| `native_wheel` | 플레이 중 마우스 휠을 굴릴 때 | `steps`, `claimed`: true로 설정하면 핫바 슬롯 전환 방지 |
| `native_command` | 채팅 명령어(슬래시 제외), 서버가 수신하기 전 | `command`, `ran`: 본인 모드의 명령어일 때 true로 설정 |
| `native_zoom` | 플레이 중 매 프레임마다 | `zoom: &mut Option<NativeZoom>`: 줌을 적용하도록 설정 |
| `native_minimap` | 매 프레임마다 | `minimap: &mut Option<NativeMinimap>`: Horizon 미니맵을 표시하도록 설정 |
| `native_mods` | 설정 > 모드에서 모드 목록을 표시할 때 | `mods`: 모드 설정 항목 및 단축키 등록 |
| `native_settings` | 모드 설정 페이지가 열릴 때 | `mod_id`, `buttons`: 버튼 라벨 등록 |
| `native_settings_click` | 설정 페이지의 버튼을 클릭할 때 | `mod_id`, `button` |

모든 후크는 `bindings`에서 선언하면 `game` 인스턴스를 전달받을 수 있습니다: `{ name = "game", ty = "&mut crate::game::Game<'_>", value = "&mut *self" }`(`native_zoom` 및 `native_minimap`의 경우 `&crate::game::Game<'_>` 및 `&*self`). 키트가 생성하는 파일에서 각각의 `bindings` 설정 예시를 확인할 수 있습니다.

### 게임 헬퍼 함수

모든 후크에서 `game` 인스턴스를 통해 호출할 수 있는 유용한 도우미 함수들입니다.

| 헬퍼 | 수행 작업 |
|---|---|
| `native_on(id)` | 플레이어가 설정 > 모드에서 모드를 켜두었는지 여부. 모든 후크에서 최우선 확인 |
| `native_playing()` | 메뉴, 채팅, 표지판 등이 열려 있지 않고 플레이 중인지 여부 |
| `native_window()` | 서버 측이 아닌 클라이언트 창의 게임 인스턴스인지 여부 |
| `native_player()` | 월드 내 플레이어 정보: `x`, `y`, `z`, `yaw`, `pitch`, `dimension`, 또는 `None` |
| `native_frame_rate()` | 현재 FPS, 가장 느렸던 프레임 타임 및 하위 1% FPS(1% low) |
| `native_clicks()` | 최근 1초 동안의 공격 및 사용 클릭 횟수 |
| `native_mapping("key.jump")` | 바닐라 조작키가 눌려 있는지 여부 및 해당 키 이름 |
| `native_mod_key(id, name, default)` | 플레이어가 단축키 `name`에 대해 지정한 바인딩 키 |
| `native_chat(text)` | 플레이어 채팅창에 메시지 한 줄 출력 |
| `native_text(batch, text, [x, y], rgb, shadow)` | HUD 화면에 텍스트 그리기 |
| `native_fill(batch, [x, y, w, h], argb)` | HUD 화면에 직사각형 채우기 |
| `native_text_width(text)` | 텍스트의 너비(GUI 픽셀 단위) |
| `native_corner_shown(corner)` | 화면 모서리가 비어 있는지 여부(F3 디버그 화면은 상단 두 곳 사용) |
| `native_setting(id, key)` / `native_set_setting(id, key, value)` | 모드 설정값 읽기 및 저장 |
| `native_data_dir(id)` | 모드 전용 폴더(모드 자체 파일 저장용) |

Horizon의 최신 버전에서는 인벤토리 옆 아이템 패널, 제작법 레시피, 크리에이티브 아이템 지급 등 더 많은 기능이 추가됩니다. 해당 기능을 사용하는 모드는 대응 버전의 Horizon을 요구하며, **확인 및 패키징** 시 이를 자동 감지하여 모드 메타데이터에 기록합니다.

### 아이디어 예시

- **CPS 카운터:** `native_clicks()`를 사용하여 HUD에 클릭 속도(CPS)를 표시.
- **키스트로크(Keystrokes):** `native_mapping("key.forward")` 등 이동 키가 눌려 있는 동안 화면의 키 박스를 점등.
- **사망 좌표 기록:** 매 틱마다 `native_player()` 위치를 기록하고, 플레이어 정보가 `None`으로 변하는 순간 마지막 사망 위치를 채팅창에 출력.
- **계산기:** `/calc 2+2` 명령어로 입력된 수식을 파싱하여 계산 결과를 반환.
- **세션 타이머:** `native_tick`에서 경과 틱을 세어 현재 플레이 세션 유지 시간을 HUD 상자에 표시.

## 현재 모드가 할 수 없는 작업

Horizon은 네이티브 모드에 위에서 설명한 후크 포인트만 제공하며 게임 엔진 전체를 개방하지 않습니다. 따라서 현재 다음 작업은 지원되지 않습니다:

- 블록, 아이템, 몹, 제작법, 텍스처 추가(이들은 `.hmod`라는 콘텐츠 모드 형식이며 본 키트로 제작하지 않습니다);
- 서버 측의 월드 생성 방식이나 몹 인공지능 변경;
- 플레이어 주변의 월드 데이터(블록, 몹, 아이템) 및 인벤토리 직접 검색;
- 서버로 채팅 메시지를 전송하거나 서버 명령어 실행.

Horizon에 새로운 후크 포인트가 추가되면 앱 업데이트를 통해 빌더에서도 해당 기능을 사용할 수 있게 됩니다.

## 문제 해결

- **런처 빌드 실패:** 런처의 모드 페이지에 오류 메시지의 마지막 줄들이 표시됩니다. Rust가 설치된 환경에서 **폴더 확인 및 패키징**을 실행하면 파일명과 줄 번호가 포함된 전체 오류를 확인할 수 있습니다. 해결하기 어려운 경우 오류 내용을 복사하여 GitHub Issue에 문의하세요.
- **"패키징되지 않음: TODO":** 패키징 도구는 코드 내에 `TODO` 주석이 남아 있으면 패키징을 거부합니다(미완성 포팅 코드를 표시하는 용도입니다). 해당 줄을 완성하거나 삭제하세요.
- **단축키가 동작하지 않음:** **설정 > 모드 > 해당 모드**를 확인하세요: 다른 모드나 Horizon 게임 본체가 동일한 키를 사용하고 있을 수 있습니다.
- **명령어가 서버로 전송됨:** 모드 ID와 명령어 이름은 반드시 소문자여야 합니다. `/<모드 ID>` 목록에 해당 명령어가 정상적으로 등록되어 있는지 확인하세요.
