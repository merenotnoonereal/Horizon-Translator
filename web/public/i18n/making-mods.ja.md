# Horizon Modの作り方

Horizon Translatorの**Modを作る**タブでは、Minecraft Java版のRustによる再実装である[Horizon](https://github.com/horizon-rust/horizon)向けのModを作成できます。コードを一行も書かずにModを作ることも、後からソースコードを開いてさらに本格的な開発を行うことも可能です。

- **コード不要：**Modに持たせたい機能にチェックを入れ、各欄に入力して**Modを作成**を押すだけ。すぐに使える`.hnmod`ファイルが出力されます。
- **コード付き：**すべてのModにRustソースコード、テスト環境、検証ボタンが同梱されます。Mod開発のスターターキットとしても活用できます。
- **安心の互換性：**キットModはHorizon開発チームがMod向けに安定性を保証している機能（「フックポイント」）のみを使用するため、Horizonの更新後もランチャー側で問題なくビルドできます。バージョンアップのたびにModを作り直す必要はありません。
- **更新通知：**アプリ起動時にGitHub上の最新バージョンをチェックしてお知らせします。新バージョンではビルダーやガイドに便利な新機能が追加されます。

## クイックスタート

1. Webサイト（またはGitHub Releasesページ）からWindowsまたはLinux用のHorizon Translatorを入手して起動します。
2. **Modを作る**タブを開きます。**ベースを選択**からサンプルを選んで**使用**を押すか、空白のModから始めます。
3. Modの**名前**を入力します。**Mod ID**は自動入力されます（同じModの新バージョンを作成する際もIDは統一してください）。
4. 必要な項目（HUDボックス、チャットコマンド、キー設定、ズーム、チャットメッセージ）にチェックを入れ、内容を設定します。
5. **Horizonに追加する**にチェックを入れたまま、**Modを作成**を押します。
6. Horizonランチャーの**Mod**ページを開き、「Horizonのネイティブビルド」の下にある**ビルド**を押します（表示されない場合は先に**設定 > ゲーム > ネイティブMod**を有効化してください）。初回ビルド時はRustのダウンロードが行われるため20～30分ほどかかりますが、次回以降は数分で完了します。
7. ゲームをプレイします。チャット欄に `/<Mod ID>` と入力すると、Modのコマンドやキー設定の一覧が表示されます。

作成されたModは `Documents/Horizon Translator/<mod id>/` に保存されます（アプリ下部で保存先フォルダを変更可能）。

## コードを書かずに作成できる機能

### HUDボックス

画面の四隅に現在座標、向いている方角、FPSなどのテキストを表示します。各行には自由なテキストとプレースホルダー（後述）を組み合わせて配置できます。F1キーで自動的に非表示になり、F3デバッグ画面と重ならない位置へ自動調整されます。文字色、背面の半透明黒枠の有無、表示・非表示を切り替えるホットキーを設定できます。プレイヤーは**設定 > Mod**から無効化することも可能です。

### チャットコマンド

`/hello` のようにプレイヤーがチャット欄に入力して実行するコマンドです。以下の処理を設定できます：

- **チャットに発言：**1行または複数行のテキストを表示（入力欄では `|` で行を区切ります）。
- **HUDボックスの表示/非表示切替。**
- **ズームの切替。**

コマンドはサーバーに送信される前にお手元のゲーム側で処理されるため、あらゆるマルチプレイサーバーでも動作します。サーバー標準のコマンド名（`/help`、`/home`、`/spawn` など）と同じ名前にするとMod側が優先されてしまうため避けてください。`/<mod id>` は常に自動生成され、Modのコマンドとキーの一覧を確認できます。

### キー設定

コマンドと同様の動作を実行できるショートカットキーです。プレイヤーは**設定 > Mod > 対象のMod**から自由にキーバインドを変更できます。キー入力はプレイ中のみ反応し、チャット入力中やメニューを開いている間は誤動作しません。

### ズーム

OptiFine風のズーム機能：拡大倍率（1.5～10倍）、長押し時のみズームするか押すごとにON/OFFを切り替えるか、望遠鏡のようなスムーズズーム、ズーム中のマウスホイールによる倍率微調整などを設定できます。ズーム中は視点移動の感度が自動的に穏やかになります。

### チャットメッセージ

- **参加時メッセージ：**ワールドに入った際にチャット欄に表示されるテキスト。
- **定期メッセージ：**プレイ中に一定分数ごとに繰り返し表示されるテキスト（ワールド参加時からの経過時間でカウント）。

メッセージはご自身の画面にのみ表示され、サーバーへ送信されることはありません。

### プレースホルダー

すべてのテキスト入力欄で使用できます。テキストが表示される際にリアルタイムの情報へ置き換わります。

| プレースホルダー | 表示内容 |
|---|---|
| `{x}` `{y}` `{z}` | 現在位置（小数点以下1桁）：`12.3` |
| `{bx}` `{by}` `{bz}` | 現在いるブロックの座標：`12` |
| `{facing}` | 方角：`North (-Z)`, `East (+X)`, `South (+Z)`, `West (-X)` |
| `{yaw}` `{pitch}` | 視線の向き（度単位） |
| `{dimension}` | ディメンション：`Overworld`, `Nether`, `End` |
| `{fps}` | 1秒あたりのフレーム数 |
| `{name}` `{version}` | Modの名前とバージョン |

### プレイヤー向け設定画面

すべてのキットModは**設定 > Mod**に個別の設定行が追加され、割り当てられたキーや各機能（HUDボックス、ズーム、参加時メッセージ、定期メッセージ）のON/OFFスイッチが表示されます。プレイヤーはここからMod全体を無効化することも可能です。

## 新バージョンの作成手順

1. **自作Modを開く…**を押し、Modのフォルダを選択します。前回の設定内容がフォームに復元されます。
2. 変更を加え、**バージョン**番号を上げます（例：1.0.0 → 1.1.0）。
3. **Modを作成**を押します。新しいバージョンは新しいフォルダ（`<mod id>-2` など）に出力され、過去のフォルダが上書きされることはありません。Horizon内の古い `.hnmod` が置き換わりますので、ランチャー側で再度ビルドしてください。

**Mod ID**は変更しないでください。HorizonはIDでModを識別するため、同一IDを保つことでプレイヤーの設定やキーバインドが引き継がれます。

## Modの配布・共有

完成した `.hnmod` ファイルを配布してください。プレイヤーはランチャーのModページから導入するか、Windowsでは `%APPDATA%\horizon\horizon-native-mods\`、Linuxでは `~/.local/share/horizon/horizon-native-mods/` にコピーしてビルドを実行します。

ネイティブModはゲーム内に直接コンパイルされ、プレイヤー自身のシステム権限で動作します（サンドボックス化されていません）。そのためランチャーはビルド前に確認画面を表示します。自身が内容を把握しているコードのみを配布し、信頼できる制作者のModのみを導入してください。

## さらに高度な開発：ソースコード

Modフォルダはそれぞれ独立した小さなRustプロジェクトになっています：

| ファイル | 説明 |
|---|---|
| `mixins/<id>/runtime.rs` | Mod本体。上部に設定（テキスト、キー、コマンド）、中盤にロジック、下部にテスト |
| `mixins/<id>/key.rs`, `hud.rs`, `command.rs`... | フック：Horizonから呼び出された際に実行（キー、HUD、コマンド、Tick） |
| `mixins/<id>/horizon-mixin.toml` | どのフックポイントでどのファイルを実行するかの対応設定 |
| `Cargo.toml` | ゲームを起動せずに `cargo test` で `runtime.rs` 内のテストを実行可能にする設定 |
| `compatibility.json` | Modが必要とするフックポイントのバージョンおよびベースとなったHorizonのコミット |
| `horizon-kit.json` | Mod作成ツールで選択した設定内容 |
| `<id>.hnmod` | パッケージ化された完成Mod |

コードを変更するには：

1. 任意のエディタ（rust-analyzer拡張機能を入れたVS Codeがおすすめ）でファイルを編集します。
2. アプリ内で**Modを作る > フォルダを確認してパッケージ化…**を選び、Modのフォルダを指定します。Rust (rustup.rs) がインストールされていればHorizonのヘルパー群に対してコンパイルチェックとユニットテストを実行します。Rustがない場合はそのままパッケージ化され、問題があればランチャーのビルド時に通知されます。その後新しい `.hnmod` が出力されHorizonに追加されます。
3. ランチャーでビルドして動作を確認します。

**手動でコードを書き換えたModに対して「Modを作成」ボタンを押さないでください：**フォームの内容でソースコードが再生成されてしまいます。手動編集後は必ず「確認してパッケージ化」を使用してください。

### コマンドラインツール（およびAIコーディングエージェント向け）

アプリに同梱されている `horizon-port.jar` を使うと、ターミナルから同様の操作や完全なコンパイルチェックを実行できます。各ModフォルダにはAIエージェント向けのコマンド一覧を記した `AGENTS.md` と、全フックポイントおよびヘルパーを解説した `HOOKS.md` が含まれています。

| コマンド | 処理内容 |
|---|---|
| `java -jar horizon-port.jar new spec.json --out DIR --horizon-src SRC` | 作成ツール仕様からModを生成（`kit-examples/` にサンプルあり） |
| `java -jar horizon-port.jar hooks --horizon-src SRC [--json]` | そのHorizonのフックポイントとヘルパー一覧、および各フックの `[[injection]]` を表示 |
| `java -jar horizon-port.jar compile DIR --horizon-src SRC` | 完全チェック：ランチャーと同様にModをHorizonのコピーに配置してコンパイル |
| `java -jar horizon-port.jar pack DIR --horizon-src SRC --compile --install` | 完全チェック、テスト、パッケージ化、Horizonへの追加を一括実行 |

`SRC` はHorizonのソースコードフォルダであり、`compile` 実行時に展開されます。`compile` にはRustとランチャーの horizon-mixins ツール（初回のネイティブビルド時に導入されます）が必要で、初回実行時は数GBの容量と数分間の時間を要します。**確認してパッケージ化**とは異なり、公開フックポイントに含まれないゲーム内部データ（`game.player`, `game.items()` など）を直接読み取るコードの整合性も検査できます。

### フックの動作原理

Horizonは要所要所で空の関数（**フックポイント**）を呼び出します。`horizon-mixin.toml` 内の各 `[[injection]]` 行により、それらの関数の先頭にご自身のファイルが注入されます。ファイル内には1つの関数が定義され、`bindings` に指定された引数を受け取ります。例えば `key.rs` はゲームインスタンス、キー名、押下/解放の状態を受け取ります：

```rust
fn my_mod_key(game: &mut crate::game::Game<'_>, key: &str, pressed: bool) {
    use crate::game::kit_my_mod as m;
    if !game.native_on(m::ID) {
        return;
    }
    if pressed && game.native_playing() && key == game.native_mod_key(m::ID, "jump_note", "key.keyboard.j") {
        game.native_chat("You pressed J");
    }
}
```

`runtime.rs` はモジュール（`crate::game::kit_<id>`）としてゲーム本体に組み込まれると同時に、プロジェクト自体の独立ライブラリとしても機能します。そのためゲームエンジンを必要としない処理（数値計算、文字列整形、Modの状態保持など）はここに記述し、`cargo test` でテスト可能です。

horizon-mixins のルール：`runtime.rs` 内では `//!` コメントや `#![...]` 属性、外部ファイルを参照する `mod x;`、`include!` マクロは使用できません。すべての処理を1ファイル内に完結させてください（インラインの `mod x { ... }` は使用可能です）。

### フックポイント一覧

これらはキットModを構成する基本要素です。関数名や引数はHorizonのバージョン間で互換性が維持されます。

| フックポイント | Horizonからの呼出契機 | 受け取る値 |
|---|---|---|
| `native_frame` | ワールド内外を問わず、毎フレーム | `elapsed: Duration` |
| `native_tick` | 毎ゲームTick（秒間20回）。シングルプレイのサーバー内でも呼出：`native_window()` で要判定 | |
| `native_hud` | HUD描画時（F1非表示時を除く） | `batch`, `corners`：`corners.place(corner, w, h)` でボックスを配置 |
| `native_key` | キーまたはマウスボタンの押下・解放時（`key.keyboard.z`, `key.mouse.left`） | `key`, `pressed` |
| `native_wheel` | プレイ中のマウスホイール操作 | `steps`, `claimed`：trueに設定するとホットバーの切り替えを防止 |
| `native_command` | チャットコマンド（先頭スラッシュなし、サーバー受信前） | `command`, `ran`：自身のModのコマンドであればtrueを設定 |
| `native_zoom` | プレイ中の毎フレーム | `zoom: &mut Option<NativeZoom>`：設定することでズームを実行 |
| `native_minimap` | 毎フレーム | `minimap: &mut Option<NativeMinimap>`：設定することでHorizonのミニマップを表示 |
| `native_mods` | 設定 > Mod でMod一覧が表示される際 | `mods`：Modの設定行とキー設定を追加 |
| `native_settings` | Modの設定画面が開かれた際 | `mod_id`, `buttons`：ボタンラベルを追加 |
| `native_settings_click` | 設定画面上のボタンがクリックされた際 | `mod_id`, `button` |

各フックは `bindings` で要求することにより `game` インスタンスを取得できます：`{ name = "game", ty = "&mut crate::game::Game<'_>", value = "&mut *self" }`（`native_zoom` と `native_minimap` の場合は `&crate::game::Game<'_>` および `&*self`）。生成されたファイル内にそれぞれの `bindings` 設定例が記載されています。

### ゲームヘルパー関数

任意のフックから `game` を介して呼び出せる便利な関数です。

| ヘルパー | 処理内容 |
|---|---|
| `native_on(id)` | プレイヤーが 設定 > Mod でModを有効にしているか。各フックの先頭で最初に確認 |
| `native_playing()` | メニュー、チャット、看板等を開いておらずプレイ中であるか |
| `native_window()` | サーバー側ではなく、ウィンドウ側のゲームクライアントであるか |
| `native_player()` | ワールド内のプレイヤー情報：`x`, `y`, `z`, `yaw`, `pitch`, `dimension`、または `None` |
| `native_frame_rate()` | 現在のFPS、最も遅かったフレーム、1% low |
| `native_clicks()` | 直近1秒間の攻撃および使用クリック数 |
| `native_mapping("key.jump")` | バニラの操作キーが押されているか、およびそのキー名 |
| `native_mod_key(id, name, default)` | キー設定 `name` に対してプレイヤーが割り当てたキー |
| `native_chat(text)` | プレイヤーのチャット欄に1行表示 |
| `native_text(batch, text, [x, y], rgb, shadow)` | HUD上にテキストを描画 |
| `native_fill(batch, [x, y, w, h], argb)` | HUD上に矩形を描画 |
| `native_text_width(text)` | テキストの横幅（GUIピクセル単位） |
| `native_corner_shown(corner)` | 指定した画面隅が空いているか（F3画面は上部2箇所を使用） |
| `native_setting(id, key)` / `native_set_setting(id, key, value)` | Mod設定の読み込みと保持 |
| `native_data_dir(id)` | Mod独自の個別フォルダ（独自ファイルの保存用） |

新しいHorizonバージョンではさらなる機能（インベントリ横のアイテムパネル、クラフトレシピ、クリエイティブでのアイテム付与など）が順次追加されます。それらを使用するModには対応するバージョンのHorizonが必要となり、**確認してパッケージ化**時に自動検出されてMod情報に記録されます。

### 作成アイデア例

- **CPSカウンター：**`native_clicks()` を使ってHUDにクリック速度を表示。
- **キーストローク表示：**`native_mapping("key.forward")` などの押下状態に合わせて画面上のキー枠を点灯。
- **デス座標リマインダー：**毎Tick `native_player()` を記録し、`None` になった瞬間に直前の死亡座標をチャットに通知。
- **計算機：**`/calc 2+2` のようにコマンド名以降の数式をパースして計算結果を表示。
- **セッションタイマー：**`native_tick` で経過Tick数を数え、今回の連続プレイ時間をHUDに表示。

## 現状まだModでできないこと

HorizonがネイティブModに提供しているのは上記のフックポイントであり、ゲームの全領域ではありません。現在以下の機能はModでは実現できません：

- ブロック、アイテム、モブ、レシピ、テクスチャの追加（これらは `.hmod` という別形式のコンテンツModであり、当キットでは作成できません）；
- サーバー側でのワールド生成やモブの挙動変更；
- プレイヤー周辺のワールド環境（ブロック、モブ、落ちているアイテム）やインベントリ内容の直接走査；
- サーバーへのチャットメッセージ送信やサーバーコマンドの実行。

Horizonに新たなフックポイントが追加された際は、アプリのアップデートを通じてビルダーから利用可能になります。

## トラブルシューティング

- **ランチャーでのビルドが失敗する：**ランチャーのModページにエラーの末尾数行が表示されます。Rustを導入した環境で**確認してパッケージ化**を実行すると、ファイル名と行番号を含む詳細なエラーを確認できます。解決できない場合はエラー内容をコピーしてGitHubのIssueでお知らせください。
- **「未パッケージ化：TODO」：**パッケージャーはコード内に `TODO` が残っていると処理を中断します（未完成の移植箇所を示す目印です）。該当行を完成させるか削除してください。
- **キーを押しても反応しない：** **設定 > Mod > 対象のMod** を確認してください。他のModやHorizon本体と同じキーが重複して割り当てられている可能性があります。
- **コマンドがサーバーに送信されてしまう：**Mod IDとコマンド名はすべて小文字である必要があります。`/<Mod ID>` の一覧に正しく登録されているか確認してください。
